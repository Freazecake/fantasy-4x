# Инструкция по проекту: фэнтезийная 4X-стратегия на C++/Qt

## Вводные

- **Жанр:** пошаговая (turn-based) 4X-стратегия в фэнтезийном сеттинге
- **Срок:** ~1.5 месяца
- **Цель:** университетский проект, фокус на защите — **рабочий геймплей** (ИИ, экономика, победа), а не глубокая архитектура или красивый GUI
- **Опыт:** C++ — хорошо, Qt — почти с нуля
- **Условие победы:** остаться единственным правителем на карте (военное или политическое поглощение)

> **Важно:** экономика и военная сфера в этом проекте — не второстепенные системы, а центральные механики, которым намеренно уделена глубина (постройки, дерево технологий, распределение населения, торговля, именные персонажи, юниты и казармы). Это осознанное расширение исходного минимального скоупа — см. раздел 7 про цену по времени и что резать первым, если не будет хватать времени.

## 1. Концепция игры

### Расы (не сбалансированы специально, бонусы по стереотипам)

| Раса | Наука | Промышленность | Торговля | Дипломатия | Военное | Рост нас. | Старт. поселение |
|---|---|---|---|---|---|---|---|
| Люди | 100 | 100 | 130 | 140 | 100 | 110 | Деревня |
| Дворфы | 90 | 180 | 90 | 40 | 150 | 70 | Горная крепость |
| Гномы | 170 | 120 | 110 | 90 | 50 | 90 | Мастерские в холмах |
| Эльфы | 150 | 60 | 100 | 110 | 90 | 40 | Лесное поселение |
| Орки | 40 | 90 | 50 | 20 | 180 | 150 | Кочевой стан |

Модификаторы — множители к базовым показателям (100 = нейтрально). Люди — универсалы без провалов, что делает их сильными именно в игре с несколькими путями победы (наука/торговля/война/дипломатия).

### Этапы игры (фазы), привязанные к событиям, а не времени

1. **Фаза 1** — до постройки первого города (важен только старт. тип поселения и рост населения)
2. **Фаза 2** — до формирования своего государства (важны военное дело и дипломатия)
3. **Фаза 3** — глобальная сцена, карта открыта/поделена государствами (важны наука и торговля — экспоненциальный эффект)
4. **Фаза 4** — финал, борьба за единственное государство на карте (решает суммарный накопленный потенциал, а не стартовые бонусы)

## 2. Экономика и ресурсы

### 2.1. Типы ресурсов

| Ресурс | Копится/тратится | Источник | На что тратится |
|---|---|---|---|
| Наука | очки, тратятся | население, назначенное в сферу | исследование технологий |
| Промышленность | очки, тратятся | население, назначенное в сферу | постройка зданий, снаряжение юнитов |
| Торговля | очки, тратятся | население, назначенное в сферу | обмен на другие очки (кроме торговли) |
| Дипломатия | очки, тратятся | население, назначенное в сферу | политические действия (в т.ч. политическая победа) |
| Население | не тратится в гражд. сферах, но безвозвратно уходит при найме юнитов | рост по модификатору расы | назначение по сферам ИЛИ найм юнитов (см. раздел 3) |
| Военная сила | отдельная система, НЕ очки | юниты, созданные из населения + промышленности | бои |

Военная сфера сознательно исключена из системы очков — сила армии считается через юниты, а не через "1 человек = 1 очко военных". Подробности — раздел 3.

### 2.2. Население как основа экономики

Население принадлежит поселению и растёт каждый ход по формуле:

```
growthPerTurn = settlement.population * baseGrowthRate * race.modifiers.growth
```

Прирост населения не тратится — это пул, который распределяется игроком (или ИИ) между 4 гражданскими сферами: наука, промышленность, торговля, дипломатия. Население можно свободно перераспределять между сферами в любой ход (мгновенно, без штрафа), включая ранее назначенное.

**Важное отличие от найма юнитов (раздел 3):** переброска между гражданскими сферами обратима и бесплатна. Отправка населения в армию — необратима: эти люди списываются из `settlement.population` насовсем.

```cpp
// core/Settlement.h
enum class Sphere { Science, Industry, Trade, Diplomacy };

struct PopulationAllocation {
    int science = 0;
    int industry = 0;
    int trade = 0;
    int diplomacy = 0;
    int idle = 0; // ещё не назначено

    int total() const { return science + industry + trade + diplomacy + idle; }
};

class Settlement {
public:
    int population = 0;
    PopulationAllocation allocation;
    // ...
};
```

### 2.3. Расчёт дохода за ход

1 человек, назначенный в сферу, даёт 1 базовое очко этой сферы. Дальше очки умножаются на модификатор расы, бонусы построек и бонус именного персонажа (раздел 2.6), если он активен для этой сферы.

```cpp
// core/Economy.h
struct TurnIncome {
    int science = 0, industry = 0, trade = 0, diplomacy = 0;
};

TurnIncome Economy::calculateSettlementIncome(const Settlement& s, const Race& race,
                                               const std::vector<Building>& built,
                                               const std::vector<Hero>& activeHeroes) {
    TurnIncome income;
    income.science   = s.allocation.science;
    income.industry  = s.allocation.industry;
    income.trade     = s.allocation.trade;
    income.diplomacy = s.allocation.diplomacy;

    // модификатор расы
    income.science   *= race.modifiers.science;
    income.industry  *= race.modifiers.industry;
    income.trade     *= race.modifiers.trade;
    income.diplomacy *= race.modifiers.diplomacy;

    // бонусы построек и именных персонажей применяются по тому же принципу,
    // как дополнительные множители на соответствующую сферу
    applyBuildingBonuses(income, built);
    applyHeroBonuses(income, activeHeroes);

    return income;
}
```

Суммарный доход игрока за ход — сумма `TurnIncome` по всем его поселениям.

### 2.4. Траты: постройки и технологии

Обе системы реализуются в полном объёме (не мгновенная постройка, а очередь с накоплением очков; дерево технологий — ветвящееся, с зависимостями).

```cpp
// core/Building.h
struct Building {
    std::string id, name;
    std::string category;        // "economic" | "military" — экономическая или военная постройка
    std::string resourceType;    // для category="economic": "science"|"industry"|"trade"|"diplomacy"; иначе ""
    float bonusMultiplier;       // используется только для category="economic"
    int industryCost;
    std::string requiredTechId;  // "" если доступна без исследований

    // поля, используемые только для category="military" (см. раздел 3)
    std::vector<std::string> unlocksUnitIds;   // какие юниты становятся доступны
    bool removesUntrainedPenalty = false;      // снимает штраф необученности
};

// core/Technology.h
struct Technology {
    std::string id, name, category;
    int scienceCost;
    std::vector<std::string> prerequisiteIds;
    std::vector<std::string> unlocksBuildingIds;
    float globalBonusMultiplier;
};
```

Прогресс хранится в `Settlement` (очередь построек) и `Player` (текущее исследование), см. раздел 4.

### 2.5. Траты: политические действия (дипломатия)

Дипломатические очки тратятся на фиксированный набор политических действий, а не свободный текст/переговоры — это то, что делает систему реализуемой в срок:

```cpp
// core/PoliticalAction.h
struct PoliticalAction {
    std::string id, name;
    int diplomacyCost;
    // эффект: альянс, вассализация/поглощение без войны, требование дани и т.п.
};
```

Один из вариантов — **политическое поглощение чужого государства** — напрямую реализует второй путь к победе, заявленный в вводных (не только военный).

### 2.6. Торговля: обмен очков

Торговые очки можно тратить на покупку очков других сфер (наука/промышленность/дипломатия), но не на покупку торговых очков ими же. Базовый курс — 1:1, модифицируется бонусами (например, +40% → 1.4:1).

**Принятое решение по механике курса:** бонус применяется на стороне покупателя — то есть свой модификатор торговли (раса + постройки + именной персонаж торговли) определяет, сколько очков игрок получает за потраченные торговые очки. Обмен идёт через общий рынок, а не как двусторонняя сделка между конкретными игроками.

```cpp
// core/TradeMarket.h
struct TradeExchangeResult {
    int spentTrade;
    int received;
    std::string receivedResourceType;
};

TradeExchangeResult TradeMarket::exchange(const Player& buyer, std::string targetResource, int tradeToSpend) {
    float rate = 1.0f * buyer.tradeBonusMultiplier; // 1.4 при +40%
    return { tradeToSpend, static_cast<int>(tradeToSpend * rate), targetResource };
}
```

Почему так, а не «продавец отдаёт больше»: расчёт зависит только от состояния самого игрока (его расы/построек/персонажа), без необходимости учитывать состояние второго участника сделки — это упрощает и код, и принятие решений у ИИ (не нужна логика двусторонних переговоров). Плата за упрощение — рынок ощущается более абстрактно, менее «живой экономикой», чем прямая торговля между игроками. Если в будущем захочется двусторонних сделок между конкретными государствами — это отдельное расширение поверх этой системы, не входит в минимальный скоуп.

### 2.7. Именные персонажи (герои)

У каждой расы — по одному именному персонажу на каждую гражданскую сферу (наука/промышленность/торговля/дипломатия), итого 4 героя на расу (военные герои — вне системы очков, не в этом разделе). Герой даёт статический бонус-множитель к своей сфере, пока активен.

```cpp
// core/Hero.h
struct Hero {
    std::string id, name, raceId;
    Sphere sphere;
    float bonusMultiplier; // например 1.2 = +20% к сфере
};
```

Герои данные, а не игровые юниты с прокачкой/перемещением — активируются сразу с начала игры (или по условию из `data/heroes.json`, если понадобится завязать на технологию/фазу). Система найма, левел-апа, гибели героя — намеренно не реализуется, это увеличило бы объём непропорционально пользе для демонстрации на защите.

### 2.8. Данные

Всё, что перечислено выше (постройки, технологии, политические действия, герои), хранится в JSON и не хардкодится:

```
data/
├── races.json
├── buildings.json
├── technologies.json
├── political_actions.json
└── heroes.json
```

## 3. Военная сфера

Военная сила сознательно не входит в систему очков раздела 2 — юниты не "покупаются" за военные очки, а создаются напрямую из двух ресурсов: **населения** (сам солдат) и **очков промышленности** (снаряжение).

### 3.1. Создание юнита

Найм юнита стоит `populationCost` населения (списывается из `settlement.population` безвозвратно, в момент постановки в очередь) и `industryCost` промышленности (накапливается по ходам, как в очереди построек, аналогично разделу 2.4).

```cpp
// core/Unit.h
struct UnitStats {
    float attack = 0.0f;
    float defense = 0.0f;
    float health = 0.0f;
};

struct Unit {
    std::string id, name;
    int tier = 0;                     // 0 = базовый юнит, 1+ = продвинутый
    int populationCost = 0;
    int industryCost = 0;             // "снаряжение"
    std::string requiredBuildingId;   // "" для tier 0, иначе id казармы/другого здания
    UnitStats baseStats;
};
```

```cpp
// core/Settlement.h — добавляется очередь найма, отдельная от очереди построек
struct RecruitmentItem {
    std::string unitId;
    int industryInvested = 0;
};

class Settlement {
public:
    // ...существующие поля (население, allocation, очередь построек)...
    std::optional<RecruitmentItem> currentRecruitment;
    std::vector<Unit> garrison; // уже готовые юниты в этом поселении
};
```

### 3.2. Казарма и штраф необученности

Казарма — постройка с `category = "military"` (раздел 2.4). Пока она не построена в конкретном поселении:

- доступен найм только юнитов tier 0 (базовых);
- их характеристики (`attack`, `defense`) применяются со штрафом необученности — юнит слабее, чем прописано в `baseStats`;
- юниты tier 1+ недоступны для найма вообще, независимо от накопленных ресурсов.

После постройки казармы: штраф снимается для новых и уже нанятых в этом поселении юнитов tier 0, и открывается найм продвинутых юнитов, перечисленных в `unlocksUnitIds` казармы.

```cpp
// core/Military.h
class MilitarySystem {
public:
    static constexpr float kUntrainedPenaltyMultiplier = 0.6f; // -40% к attack/defense без казармы

    // населением платится сразу при постановке в очередь, промышленность — по ходам
    bool queueUnit(Settlement&, const Unit&, const Player&);

    // юнит tier 0 без казармы -> baseStats * kUntrainedPenaltyMultiplier
    // юнит tier 0 с казармой, юнит tier 1+ (доступен только если казарма построена) -> baseStats как есть
    UnitStats effectiveStats(const Unit&, bool hasBarracks) const;

    // проверка возможности найма: tier 0 доступен всегда,
    // tier 1+ только если requiredBuildingId есть в settlement.constructedBuildingIds
    bool canRecruit(const Settlement&, const Unit&) const;
};
```

`kUntrainedPenaltyMultiplier` — единая константа на все расы и юниты, не в JSON: это единственный тюнинг-параметр всей подсистемы, выносить его в данные excessive для срока. Если понадобится настраивать его по расе/юниту отдельно — можно позже перенести в `units.json`.

### 3.3. Данные

```
data/
└── units.json   // список Unit: id, name, tier, populationCost, industryCost, requiredBuildingId, baseStats
```

Казармы описываются в `buildings.json` как обычная запись с `category: "military"` — отдельный файл под здания заводить не нужно.

### 3.4. Что осознанно не входит в этот раздел

- **Формулы разрешения боя** (как именно `attack`/`defense`/`health` двух юнитов превращаются в исход столкновения) — отдельное решение, не зафиксировано здесь.
- **Передвижение юнитов по карте** — считается частью Tile/Map (раздел 4), не этого раздела.
- **Найм/прокачка/гибель именных военных героев** — по аналогии с гражданскими героями (раздел 2.7) осознанно не реализуется.

### 3.5. ГUI

Отдельная панель под казармы не нужна — очередь найма юнитов встраивается в уже существующую `SettlementPanel` (раздел 4) как второй список рядом с очередью построек: своя, т.к. тратит население, а не только промышленность.

## 4. Архитектурное решение

### Почему пошаговая, а не real-time

RTS требует синхронизации ИИ/экономики/сети в реальном времени — сильно сложнее для новичка в Qt. Turn-based — стандарт жанра 4X (Civilization, MoO, Age of Wonders), не режет твою идею, а следует канону жанра.

### Разделение на слои — САМОЕ ВАЖНОЕ РЕШЕНИЕ

```
core/  — чистый C++/STL, НЕ ЗНАЕТ про Qt вообще
ai/    — логика решений ИИ, тоже на STL
gui/   — Qt-обёртка, которая читает core/ и рисует
data/  — races.json и другие данные
```

**Почему это критично при слабом знании Qt:**
- core/ тестируется консольно, без единого окна — быстрая отладка
- Меньше риска багов с моделью владения объектами в Qt (parent-child деревья vs RAII/unique_ptr)
- На защите это доказывает осознанную архитектуру

### Структура файлов

```
src/
├── core/
│   ├── Race.h/cpp             // данные расы + модификаторы
│   ├── Settlement.h/cpp       // город/поселение, население, распределение по сферам
│   ├── Player.h/cpp           // игрок (человек или ИИ), исследования, ресурсы
```

## 5. Что учить из Qt (минимальный набор)

**Обязательно:**
- `QMainWindow`, `QWidget`
- `QGraphicsView` / `QGraphicsScene` / `QGraphicsItem` — отрисовка карты
- Signals & Slots (`connect(...)`) — САМОЕ важное в Qt, механизм событий
- `QString` (только конвертация на границе с core)

**Не обязательно, но пригодится:**
- `QTimer`, `QPushButton`, `QLabel`, `QVBoxLayout`

**Не понадобится вообще:**
- Qt Containers (используй `std::vector` везде)
- QThread/многопоточность (в пошаговой игре не нужна)

**Как учить быстро:**
1. Официальный туториал "Qt Widgets and Layouts" (~1-2 часа)
2. Туториал по "QGraphicsView tile-based game / grid" — под конкретную задачу карты
3. Signals & Slots — 10-15 минут документации, дальше это база

## 6. ИИ — минимально жизнеспособный подход

Не нейросети — **Utility AI**: каждый ход считаем несколько "скор" (score) для возможных стратегий и выбираем максимум, с элементом случайности против детерминизма.

```cpp
class AIController {
public:
    Action decideNextAction(const Player& self, const GameState& state);
private:
    float scoreExpand(const GameState&);
    float scoreAttack(const GameState&);
    float scoreDevelop(const GameState&);

    // score-функции под экономику из раздела 2
    float scoreAllocatePopulation(const Settlement&, Sphere target);
    float scoreBuild(const Settlement&, const Building&);
    float scoreResearch(const Player&, const Technology&); // только если prerequisiteIds выполнены
    float scorePoliticalAction(const Player&, const PoliticalAction&);
    float scoreTradeExchange(const Player&, const std::string& targetResource);

    // score-функция под военную сферу из раздела 3
    float scoreRecruitUnit(const Settlement&, const Unit&); // учитывает наличие казармы (штраф/tier)
};
```

Фаза игры (enum) должна влиять на веса этих скор-функций — например, в Фазе 2 вес scoreAttack/scoreExpand/scoreRecruitUnit выше, в Фазе 3 — scoreDevelop, scoreResearch и scoreTradeExchange (наука/торговля).

ИИ при распределении населения (`scoreAllocatePopulation`) должен уметь пересматривать уже назначенных людей между сферами каждые несколько ходов, а не только распределять новый прирост — иначе он не сможет адаптироваться к смене фазы. При этом `scoreRecruitUnit` должен учитывать, что найм населения необратим (раздел 2.2, 3.1) — ИИ не должен наивно оголять экономику ради армии без учёта фазы игры.
